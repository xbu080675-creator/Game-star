# Game Star Box 0.4.22 / versionCode 35

## 目标

修复 0.4.19~0.4.21 引入真实游戏库后出现的明显卡顿，重点处理本机应用枚举、图标编码和游戏启动校验热路径。该版本是性能热修，不扩大功能和权限面。

## 问题定位

0.4.21 实机出现“非常卡”的主要高风险点来自 `InstalledGameCatalog`：

- 初次读取游戏库时，对所有 `MAIN + LAUNCHER` 应用逐个加载 Drawable、绘制 Bitmap、PNG 压缩并 Base64 编码；应用越多，阻塞越明显。
- 同一自动识别游戏的图标同时写入 `autoGames` 与 `launchables` JSON，造成重复 Base64 payload、额外序列化和 WebView bridge 传输成本。
- 更严重的是 `createValidatedLaunchIntent()` 的安全 allow-list 校验会调用 `isVisibleLauncherPackage()`，而旧实现再次执行完整 `queryEntries()`；也就是说每次点击启动游戏，都可能重新扫描应用并重新编码全部图标。
- 这条路径虽然保持了安全白名单，但实现方式不适合作为交互热路径。

## 本版修复

- `InstalledGameCatalog` 的 launcher allow-list 与视觉 catalog 分离。
- 首次 catalog 构建后缓存 `Set<String>` launcher package allow-list。
- 游戏启动校验优先直接读取缓存 allow-list，不再重新执行图标编码。
- 如果启动发生在 catalog 尚未构建前，fallback 只执行 metadata-only `MAIN + LAUNCHER` 包名查询，不加载 label、不加载 Drawable、不创建 Bitmap、不做 PNG/Base64。
- `launchables` 列表改为 metadata-only，不再携带所有普通应用图标。
- 只有 Android 自动识别为游戏的 `autoGames` 在首屏需要展示时才编码图标。
- 自动识别游戏图标不再在 `autoGames` 和 `launchables` 两份 JSON 中重复传输。
- 首屏游戏图标尺寸由 128px 收到 96px，PNG 压缩质量由 88 调到 82，降低 bridge payload 和 WebView 解码压力；不影响启动逻辑。
- `invalidate()` 同时清理 catalog JSON 与 launcher allow-list，避免缓存状态不一致。

## 安全边界

- 仍然不申请 `QUERY_ALL_PACKAGES`。
- 启动目标仍必须属于当前可见 `MAIN + LAUNCHER` allow-list。
- 没有因为性能优化绕过包名校验。
- 不新增 Shizuku、shell、root、Usage Access、Accessibility 或 Settings 写入。
- 不修改 REDMAGIC 控制面。

## 架构职责

```text
PackageManager MAIN/LAUNCHER
        ├─ metadata-only allow-list ──> launch validation hot path
        └─ catalog discovery
               ├─ auto game -> icon encode (small set)
               └─ generic launcher -> metadata only
```

安全校验与视觉资源生成不再共用高成本函数。

## 实机测试重点

1. 从 0.4.21 OTA 到 0.4.22 后，主界面进入和左右切换应明显恢复流畅。
2. 游戏库首次打开不应因本机安装应用较多而长时间卡住。
3. “添加游戏”列表允许普通 launcher 应用没有图标占位，但滚动应流畅。
4. 点击真实游戏“启动”时不应再出现明显卡顿后才跳转。
5. 自动识别游戏仍应显示真实图标、名称和包名。
6. 手动添加的应用仍可正常加入、移除和启动。
7. `GameSession` 状态链与 Quick Menu 状态不得回归。
8. 0.4.14 启动视觉、OTA 固定签名、自更新链不得回归。

## 后续

如果 0.4.22 实机仍有残余卡顿，下一层会继续测量 WebView DOM 重绘与 Runtime listener 频率；普通 launcher 图标后续若需要恢复，将采用按需 lazy icon，而不是重新回到全量同步 Base64 编码。
