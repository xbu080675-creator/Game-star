# Game Star Box 0.4.23 / versionCode 36

## 目标

修复 0.4.21/0.4.22 实机启动动画明显掉帧、呈现“一卡一卡”的问题。优先保证已验收的 GAME STAR BOX 启动动画帧 pacing 稳定，不在启动关键路径并发执行游戏库、Game Session、Quick Menu 等运行时初始化。

## 根因

- `native-update.js` 在启动动画进行过程中立即注入 `game-library.js`、`session-runtime.js`、`quick-menu-runtime.js` 与 `menu-music.js`。
- `game-library.js` 会同步读取 `GSBGames.catalog()` 并进行 DOM 重绘；即使 0.4.22 已降低图标编码成本，这批工作仍会与 WebView 启动动画争用主线程/渲染资源。
- 0.4.16 起 Boot Runtime 每约 180 ms 根据 `BootSnapshot` 改写 `bootAudio.playbackRate`；而现有启动视觉又以音频 `currentTime` 为主时钟，因此频繁改变音频时钟会放大视觉 frame pacing 抖动。

## 本版修复

- 启动动画恢复固定原生 1.0x 音频时钟，不再在动画进行中反复改写 `playbackRate`。
- BootSnapshot 仍保留为真实后端启动状态源，并继续写入 `data-gsb-boot-phase` / `data-gsb-boot-progress`，只是本版不再用它直接驱动音频变速。
- Boot 状态轮询从 180 ms 降频到 320 ms，减少 WebView/Java bridge 在动画阶段的干扰。
- 游戏库、Game Session Runtime、Quick Menu Runtime、菜单音乐全部延迟到启动层 `.done` 后再注入。
- 后启动初始化优先通过 `requestIdleCallback` 执行；不支持时使用短延迟 fallback。
- 增加 5.2 s fail-safe：即使视觉层异常没有标记 `.done`，运行时功能也不会永久不加载。
- 0.4.22 的游戏目录性能修复继续保留，不回退。

## 架构决定

启动动画与后端真实进度仍然是两条有关联但不同职责的链：

```text
BootOrchestrator -> 真实 readiness/state
                     ↓
                 WebView bridge
                     ↓
              Boot telemetry only

GAME STAR BOX boot audio/visual -> 稳定 1.0x 主时钟
                                  ↓
                              boot done
                                  ↓
             Game Library / Session / Quick Menu runtime
```

后续如果重新做“真实进度驱动动画”，采用阶段 hold/resolve 或独立视觉时间轴，不再通过高频改写音频 playbackRate 实现。

## 安全边界

- 不新增权限。
- 不新增 Shizuku、root、shell、Settings 写入。
- 不修改 REDMAGIC 控制面。
- 不改变 OTA 签名与验证链。
- 仅调整 WebView 启动调度与运行时脚本加载时机。

## 实机测试重点

1. 冷启动动画应恢复连续流畅，不应出现明显逐段卡顿。
2. GAME STAR BOX 音画同步不能回退。
3. 启动结束后首页真实游戏仍应正常出现。
4. 游戏库、Game Session、Quick Menu 均应在进入主界面后正常工作。
5. 菜单音乐应在启动结束后正常加载。
6. 0.4.22 的“打开游戏库/点击启动游戏”性能修复必须保留。
7. OTA、固定签名、REDMAGIC capability audit 不得回归。
