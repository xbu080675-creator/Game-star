# Game Star Box 0.4.27 / versionCode 40

## 版本目标

把首次启动从“观看一段启动动画”改成“亲手完成游戏硬件适配并点火”，并根据 REDMAGIC 9 Pro+ 实机结果建立完整的肩键校准链：**临时激活 REDMAGIC 肩键场景 → 读取可信 SAR F7/F8 → Core 语义状态机 → 校准结束恢复原场景。**

## 首次启动流程

```text
纯黑 Starting Window
  ↓
横屏游戏手机硬件轮廓
  ↓
TAP L
  ↓
HOLD L（4 级震动 / 画面微共振）
  ↓
TAP R
  ↓
HOLD R（4 级震动 / 画面微共振）
  ↓
HOLD L + R
  ↓
整机点火：肩键视觉 + 主马达 + 屏幕共振 + 音效同步增强
  ↓
短暂收黑 / 静默
  ↓
GAME STAR BOX
  ↓
Runtime Gate 打开 → 主界面
```

首次完成后写入本地 `shoulder_calibrated_v1`。后续启动走缩短版自动点火，不再要求重复校准。

## REDMAGIC 9 Pro+ 两轮实机结论

### 第一轮：灯亮，但竞界收不到肩键

实体肩键灯效有响应，但标准 Android `L1/R1` KeyEvent 没有进入 Activity。公开平台取证与实机现象一致：Nubia/REDMAGIC 肩键位于 SAR input device，左键为 Linux `KEY_F7` / `0x41`，右键为 `KEY_F8` / `0x42`。

因此加入：

- 普通 `AndroidShoulderKeyAdapter`：L1/L2/R1/R2 + F7/F8；
- Shizuku SAR Reader：只读取设备名包含 `nubia_tgk_aw_sar` 的 `/dev/input/eventN`，只向 Core 输出 LEFT/RIGHT DOWN/UP。

### 第二轮：不进红魔游戏中心，SAR 本身没有被激活

第二轮实机确认：即使已经有 Reader，若没有先进入红魔游戏中心打开肩键，竞界仍收不到肩键；手动进入游戏中心开启后才可使用。

该结果确认缺失的是 **REDMAGIC game scene / SAR enable 前置层**，而不是继续猜新的 KeyCode。

0.4.27 hotfix 因此新增 typed、可逆的临时 Scene 激活：

```text
BootMainActivity foreground
  ↓
Shizuku UserService
  ↓
保存三项 REDMAGIC Global Settings 原值
  ↓
nubia_game_scene = 1
nubia_game_mode = 1
cc_game_mis_operate = 0
  ↓
等待厂商框架短暂稳定
  ↓
发现可信 nubia_tgk_aw_sar
  ↓
只读 F7/F8 DOWN/UP
  ↓
ShoulderBootInputHub
  ↓
ShoulderBootStateMachine
  ↓
校准完成 / Activity 离开前台
  ↓
停止 Reader → 恢复三项原值 → 解绑 UserService
```

竞界不设置 `virtual_game_key`，不主动拉起完整 Game Space。

## Core / Adapter 边界

### Core

`ShoulderBootStateMachine`：

- 不引用 Android、REDMAGIC、Shizuku、Settings、WebView 或 `/dev/input`；
- 只处理 `LEFT / RIGHT + DOWN / UP`；
- 强制顺序 `LEFT_TAP → LEFT_HOLD → RIGHT_TAP → RIGHT_HOLD → BOTH_HOLD → IGNITING → COMPLETE`；
- 单侧长按 1200 ms，联合点火 1450 ms；
- 输出 0~100 progress 和 0~4 haptic level。

`ShoulderBootInputHub` 仅作为进程内语义 rendezvous。平台 Adapter 发布 LEFT/RIGHT DOWN/UP，Core 状态机消费；Core 不知道 Shizuku、Settings、设备路径或厂商实现。

### 普通 Android Adapter

`AndroidShoulderKeyAdapter`：

- `KEYCODE_BUTTON_L1/L2` → LEFT；
- `KEYCODE_BUTTON_R1/R2` → RIGHT；
- `KEYCODE_F7` → LEFT；
- `KEYCODE_F8` → RIGHT。

### REDMAGIC Privileged Adapter

组件：

- `IRedMagicShoulderReader.aidl`
- `IRedMagicShoulderCallback.aidl`
- `RedMagicShoulderReaderService`
- `RedMagicShoulderPrivilegedAdapter`
- `RedMagicShoulderBootstrapProvider`

AIDL 只暴露类型化动作：

- `enableCalibrationScene()`
- `restoreCalibrationScene()`
- `detectDevices()`
- `startReading(callback)`
- `stopReading()`

调用方不能提供 shell 命令、Settings key/value、namespace、input 路径或 keyCode。

## REDMAGIC Scene 激活边界

UserService 固定使用 `/system/bin/settings`，仅允许 `global` namespace 的三项键：

- `nubia_game_scene`
- `nubia_game_mode`
- `cc_game_mis_operate`

进入校准前读取并保存原值；只有原值为空或安全整数时才继续。退出时恢复原值，原本不存在的键则删除。

竞界普通 App 进程 **不会永久获得 `WRITE_SECURE_SETTINGS`**；临时写入发生在受限 Shizuku UserService 的 shell/root identity 中。

明确禁止：

- `virtual_game_key`；
- 其他 REDMAGIC / Android Settings key；
- Secure/System namespace 写入；
- 通用 shell；
- `sendevent` / `input keyevent` / `input motionevent`；
- uinput / 虚拟手柄；
- 屏幕点击注入；
- WebView/网络提供命令、路径、Settings key/value。

## SAR Reader 边界

Privileged Service 自行执行固定 `/system/bin/getevent -pl` 发现设备；调用方不能传路径。

只有同时满足：

- 设备节点匹配 `/dev/input/eventN`；
- 设备名包含 `nubia_tgk_aw_sar`；

才可进入固定 `/system/bin/getevent -ql <validated-node>` Reader。

Reader 只解析：

- `KEY_F7` / `0x41` → LEFT；
- `KEY_F8` / `0x42` → RIGHT；
- DOWN / UP。

其他原始输入不跨 Binder。

## Shizuku 行为

- 同一包名此前已经授权过 Shizuku 时，不要求每次重新弹授权窗；
- 首次未授权时才调用一次权限请求；
- Binder 在 Activity 启动初期尚未送达时进行有限次数短间隔重试；
- Shizuku 未运行、权限被拒绝或 UserService 失败时，不阻塞竞界普通功能，保留触摸恢复入口。

## 生命周期与 Runtime Gate

首次启动：

- 主 `index.html` WebView 后台加载但保持 `INVISIBLE`；
- 旧启动层立即 `done`，旧 `fairy_boot.ogg` 停止；
- `GSBRuntime.bootGateOpen()` 在点火完成前为 false；
- 游戏库、Session、Quick Menu、菜单音乐等模块等 Gate 打开后才加载；
- REDMAGIC shoulder calibration capability 只在 `BootMainActivity` 前台且尚未完成校准时运行；
- pause/stop/destroy 或校准完成：停止 Reader → 尝试恢复 REDMAGIC Scene → 解绑 UserService；
- `shoulder_sar_migration_0427_v1` 仅执行一次，用于覆盖旧原型后重置旧肩键校准标记，强制重新测试真实硬件链。

## 触摸恢复入口

启动页顶部 L/R 区域继续保留本地触摸入口，用于：

- Shizuku 不存在或未运行；
- 用户拒绝授权；
- REDMAGIC Scene 激活失败；
- 未识别到可信 SAR；
- 非 REDMAGIC / 无肩键设备；
- 开发阶段单独验证震动和画面节奏。

触摸入口不会冒充实体肩键识别成功。
