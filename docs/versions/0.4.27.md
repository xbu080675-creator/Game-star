# Game Star Box 0.4.27 / versionCode 40

## 版本目标

0.4.27 将首次启动升级为真正的 **Hardware Awakening / Hardware Playground**：用户不是观看一段开机动画，而是亲手把手机本身玩一遍；与此同时后台完成第一次进入竞界所需的阻塞准备，只有真实硬件序列、Playground 演出和后台首屏都达到允许条件，系统才进入最终点火。

同时保留 REDMAGIC 9 Pro+ 已实机验证的肩键链：临时激活 REDMAGIC game scene → 读取可信 SAR F7/F8 → Core 语义输入 → 校准结束恢复原场景。

## 两条并行时间轴

### Hardware Awakening Core

Core 状态机：

`LEFT_TAP -> LEFT_HOLD -> RIGHT_TAP -> RIGHT_HOLD -> BOTH_HOLD -> ARMED -> IGNITING -> COMPLETE`

L+R 长按达标后只进入 `ARMED`，不会自行进入 `IGNITING`。

### First Boot Provisioning

`FirstBootProvisioningCoordinator` 跟踪三个阻塞准备项：

1. `CORE_RUNTIME`：原 BootOrchestrator 的 Core / Capability / REDMAGIC Probe / Session / WebView 阻塞阶段完成；
2. `GAME_CATALOG`：`InstalledGameCatalog.catalogJson()` 在独立后台线程预热完成；
3. `MAIN_SURFACE`：隐藏主 WebView 已加载游戏库、Session、Quick Menu、滚动/手势运行时，并完成至少两帧首屏渲染。

当前 `IgnitionGate = hardwareReady AND provisioningReady`。

只有 Gate open，`BootMainActivity` 才能调用 `ShoulderBootStateMachine.releaseIgnition()`。

v5 Playground 已知结构限制：Motion / Touch / Haptic / Thermal 暂时属于 presentation-side sequencing；左右单侧校准完成后 Core 已处于 `BOTH_HOLD`。正常演出不会提示用户提前 L+R，但如果中途故意同时长按两个实体肩键，理论上可能提前进入 ARMED。下一轮硬化必须把 `playgroundComplete` 提升为平台无关 Core Gate，不允许用 UI flag 或延时掩盖。

## REDMAGIC 肩键实机链

REDMAGIC 9 Pro+ 实机已经确认：

1. 肩键灯效可以工作，但普通 Android L1/R1 KeyEvent 不一定进入竞界；
2. 肩键底层可表现为 Nubia SAR F7/F8；
3. 仅 Reader 不足，必须先激活 REDMAGIC game scene/SAR 硬件链；
4. 竞界通过独立 Shizuku UserService 保存原 Scene，临时写固定三项 REDMAGIC Global Settings，读取可信 `nubia_tgk_aw_sar` F7/F8，退出后恢复原值；
5. 不设置 `virtual_game_key`，不拉起完整 Game Space，不做输入注入，不永久授予普通 App `WRITE_SECURE_SETTINGS`。

详细安全合同继续见：

- `docs/ENGINEERING_CONSTITUTION_SHOULDER_INPUT_0.4.27.md`
- `app/src/main/java/com/xbu/esportscenter/privileged/SHOULDER_READER.md`

## 物理马达修正

REDMAGIC 9 Pro+ 实机暴露过一个重要问题：早期 Hardware Awakening 的 WebAudio 含有 48 Hz 持续 sawtooth hum，以及 58→31 Hz、96→38 Hz、74→46 Hz 等 sub-bass 点火声。用户连接蓝牙耳机后，这些所谓“震动”仍从耳机输出，证明它们属于扬声器音频而不是手机物理马达。

因此本轮明确废止“低频声音模拟触觉”的实现：

- `shoulder-boot.html` 删除持续 hum / humGain / startHum / stopHum；
- 启动音频只负责可听的机械/电子提示，不再承担任何触觉职责；
- `HardwareAwakeningMotorDriver` 触觉只允许经 Android `Vibrator` / `VibratorManager` 输出；
- Android 12+ 使用 `VibratorManager.getDefaultVibrator()`；
- Android 13+ 使用 `VibrationAttributes.USAGE_HARDWARE_FEEDBACK`；
- Manifest 固定要求 `android.permission.VIBRATE`；
- REDMAGIC SAR Scene 激活完成后先发一个纯物理短脉冲，作为主马达链路确认；
- 左/右点按、左右长按四级递进、L+R 联合长按与最终点火均使用物理马达波形；
- 所有马达异常必须记录，不再静默吞掉异常。

稳定马达日志前缀：`[GSB-HAPTIC]`。

关键错误码：

- `GSB-HAPTIC-NO-VIBRATOR-SERVICE`
- `GSB-HAPTIC-NO-PHYSICAL-MOTOR`
- `GSB-HAPTIC-VIBRATE-FAILED`
- `GSB-HAPTIC-CAPABILITY-PROBE-FAILED`
- `GSB-HAPTIC-CANCEL-FAILED`

覆盖安装一次性迁移：`hardware_motor_migration_0427_v3`。

## 可玩 Hardware Playground v5

v5 不再满足于“看硬件剖视”，而是要求用户实际操作手机完成启动关卡。

### Native Motion

新增 `HardwarePlaygroundMotionAdapter`：

- 使用 Android `SensorManager`；
- 优先 `TYPE_GAME_ROTATION_VECTOR`，回退 `TYPE_ROTATION_VECTOR`；
- Native 只向启动页发布语义 `pitch / roll`；
- 约 28 ms 最小派发间隔；
- pause / finish / destroy 停止采样；
- 无可用传感器时才允许页面拖动作为有限兜底。

稳定日志：`[GSB-PLAYGROUND]`。

### Haptic Materials

新增 `HardwarePlaygroundHapticAdapter`，三种可玩的真实物理触觉：

- `DETENT`：短促机械止挡；
- `RATCHET`：多段齿轮脉冲；
- `LATCH`：更重的分段锁止。

Android S+ 使用 `VibratorManager.getDefaultVibrator()`，Android T+ 使用 `USAGE_HARDWARE_FEEDBACK`。该 Adapter 没有音频输出，因此蓝牙耳机不可能承载这些“触觉”。

稳定日志：`[GSB-PLAY-HAPTIC]`。

### Touch Glass

页面 Canvas 默认不接管触摸；只有 TOUCH 关卡激活后才开启 pointer input。用户通过真实触摸划动擦除遮罩，而不是点“下一步”。

### Thermal Model

当前只做 `THERMAL FAN MODEL` 可玩模型：用户绕转子拖动形成 airflow 演出。**尚未声称或尝试控制 REDMAGIC 真风扇。** 真实风扇能力只有在厂商接口被验证后，才允许通过独立 typed/reversible Adapter 接入；禁止猜测 Settings/sysfs/shell 写法。

覆盖安装旧测试包无需清数据，会完整运行一次 Hardware Playground；成功完成后恢复 FAST 启动。

## Core / Adapter 边界

Core 当前包含：

- `FirstBootProvisioningCoordinator`
- `IgnitionGate`
- `ShoulderBootStateMachine.ARMED`

Core 不引用 Android、WebView、PackageManager、Shizuku、REDMAGIC Settings、SensorManager 或 Vibrator API。

平台层负责：

- 实体肩键输入翻译；
- REDMAGIC SAR 激活/读取；
- 游戏目录后台预热；
- 隐藏 WebView hydrate；
- `HardwareAwakeningMotorDriver` 肩键/点火物理触觉；
- `HardwarePlaygroundMotionAdapter` 原生姿态输入；
- `HardwarePlaygroundHapticAdapter` 三种物理材质；
- Hardware Playground presentation；
- 将语义 READY 状态交给 Core Gate。

## 生命周期

- Activity 切后台时停止当前持续振动和 Motion sensor sampling；
- Haptic Playground adapter 在 pause / finish / destroy 时 cancel；
- 未完成按压不得因 pause/stop 被误判完成；
- REDMAGIC SAR Reader / Scene 激活按独立 Privileged Adapter 生命周期在后台/退出时恢复；
- Provisioning 线程在 Activity destroy 时停止；
- 首次完成后写入 `shoulder_calibrated_v1`；后续启动可走 FAST hardware wake，但仍必须经过相同 IgnitionGate。

## Preview 前硬门槛

- 红魔 9 Pro+ 不预先进 Game Space 也能直接激活并读取实体左右肩键；
- 蓝牙耳机连接状态下，耳机只能听到启动音，手机触觉必须来自机身物理马达；
- Motion 阶段原生手机姿态必须低延迟驱动画面；
- Touch Glass 必须跟手，不得被透明 overlay 抢触摸；
- `DETENT / RATCHET / LATCH` 三种波形必须在机身上可明显区分；
- Thermal Model 必须明确只是模型，不冒充真风扇控制；
- 最终 L+R 的高潮必须明显；
- `CORE_RUNTIME / GAME_CATALOG / MAIN_SURFACE` 任一未完成时不得最终点火；
- 主界面第一次可见时游戏卡片、Quick Menu、Session 状态已经完成首屏 hydrate；
- Activity pause/stop 不残留 sensor listener 或持续振动；
- SAR Reader / REDMAGIC Scene 退出后恢复原状态；
- OTA 自更新特权链无回归；
- **在合 main 前必须把 Playground Completion 提升为 Core Gate，封死中间关卡提前 L+R 的原型漏洞。**
