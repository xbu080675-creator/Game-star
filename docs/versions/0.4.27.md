# Game Star Box 0.4.27 / versionCode 40

## 版本目标

把首次启动从“观看一段启动动画”改成“亲手完成游戏硬件适配并点火”。本版是肩键交互原型，重点验证输入节奏、分级震动、画面共振、音效和 Runtime Gate，不宣称已经完成 REDMAGIC 厂商肩键接管。

## 首次启动流程

```text
纯黑 Starting Window
  ↓
横屏游戏手机硬件轮廓
  ↓
TAP L
  ↓
HOLD L（4 级震动 / 画面微共振）
  ↓
TAP R
  ↓
HOLD R（4 级震动 / 画面微共振）
  ↓
HOLD L + R
  ↓
整机点火：肩键视觉 + 主马达 + 屏幕共振 + 音效同步增强
  ↓
短暂收黑 / 静默
  ↓
GAME STAR BOX
  ↓
Runtime Gate 打开 → 主界面
```

首次完成后写入本地 `shoulder_calibrated_v1`。后续启动走缩短版自动点火，不再要求重复校准。清除应用数据可重新进入首次校准。

## Core / Adapter 边界

### Core

新增 `ShoulderBootStateMachine`：

- 不引用 Android、REDMAGIC、Shizuku、Settings 或 WebView API；
- 只处理语义输入 `LEFT / RIGHT + DOWN / UP`；
- 强制状态顺序：`LEFT_TAP → LEFT_HOLD → RIGHT_TAP → RIGHT_HOLD → BOTH_HOLD → IGNITING → COMPLETE`；
- 单侧长按目标 1200 ms；联合点火目标 1450 ms；
- 输出 0~100 progress 和 0~4 haptic level。

### Android Adapter

新增 `AndroidShoulderKeyAdapter`：

- 当前只映射标准 `KEYCODE_BUTTON_L1/L2` 与 `KEYCODE_BUTTON_R1/R2`；
- 不猜测 REDMAGIC 电容肩键私有键值；
- 首次校准期间未识别 KeyEvent 只记录 `[GSB-BOOT] raw key ...` 日志，便于实机取证；
- 后续若 REDMAGIC 肩键不走标准 KeyEvent，新增独立 REDMAGIC Adapter，不修改 Core 状态机。

## 视觉与音频

新增 `shoulder-boot.html`，不使用抽象 loading 圈作为视觉主体：

- 主体是横屏游戏手机硬件轮廓；
- 左右肩键作为实际交互入口；
- 长按 4 个等级逐步增加设备微振幅、屏幕回波频率与音效低频；
- L+R 点火阶段左右肩键向中心收束，整机共振达到峰值后收黑；
- 最终标记由“左右控制区 + 中央屏幕”结构生成，并显示 `GAME STAR BOX`；
- 启动阶段不显示中文“竞界”。

当前音效使用 Web Audio 实时合成，仅用于验证节奏与触感；最终 Sonic Logo 可在交互节奏验收后替换为正式音频资产。

## 触觉策略

- TAP / 阶段确认：短 Click；
- HOLD level 1~4：重复波形逐级缩短间隔并提高振幅；
- IGNITING：一次性逐级增强的整机波形；
- 尊重 Android `HAPTIC_FEEDBACK_ENABLED`；
- 不宣称左右肩键存在独立物理马达，本版使用整机 Vibrator 与肩键局部视觉共同制造方向感。

## Runtime 隔离

首次启动时：

- 主 `index.html` WebView 在后台加载但保持 `INVISIBLE`；
- 旧 WebView 启动层被立即标记 `done`，`fairy_boot.ogg` 被暂停；
- `GSBRuntime.bootGateOpen()` 在肩键点火完成前返回 `false`；
- `native-update.js` 即使观察到旧 boot 已结束，也必须等待新 Native Gate；
- 游戏库、Session Runtime、Quick Menu、菜单音乐等后启动模块不会在用户校准时抢占前台动画资源。

## 开发触摸兜底

`shoulder-boot.html` 顶部 L / R 区域提供本地触摸测试入口，仅用于当前原型在未知厂商肩键路径下验证交互节奏。正式 REDMAGIC 输入路径完成后应保留为恢复/无肩键设备兼容能力，而不是冒充实体肩键识别成功。

## 安全边界

本版本：

- 不新增权限；
- 不调用 Shizuku；
- 不执行 shell；
- 不写 REDMAGIC / Android Settings；
- 不扩大 WebView 通用执行面；
- 新 JS Bridge 仅暴露 `mode / ready / touch / startFast / visualComplete` 的启动专用语义动作；
- 现有自更新安全链和 REDMAGIC 只读能力边界不变。

## 实机测试矩阵（红魔 9 Pro+）

1. 冷启动不得显示旧圆环启动动画或 `fairy_boot.ogg`。
2. 首次启动应严格要求 TAP L → HOLD L → TAP R → HOLD R → L+R。
3. TAP 阶段长按超过 700 ms 不得误当成有效点按。
4. 单侧 HOLD 未达到 100% 提前松手，进度和震动必须归零，不进入下一阶段。
5. 4 个 HOLD level 的主马达节奏应有清晰递进，但不得造成明显刺手或持续最大振幅。
6. L+R 只按一个时不得累计点火进度；任一侧提前松开应清零。
7. 标准游戏手柄 L1/R1、L2/R2 应可驱动流程。
8. 红魔实体肩键若产生 KeyEvent，记录实际 keyCode/source/device；若没有 KeyEvent，进入 REDMAGIC Adapter 取证，不猜值。
9. 完成后主界面应无旧启动闪回，Runtime 模块只在 Gate 打开后加载。
10. 第二次启动应走 FAST 模式，不重复首次校准。
11. 系统关闭触觉反馈后，流程仍可完成，只取消 Vibrator 输出。
12. Activity 中途切后台不得留下持续振动。
