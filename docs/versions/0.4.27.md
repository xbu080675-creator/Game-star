# Game Star Box 0.4.27 / versionCode 40

## 版本目标

把首次启动从“观看一段启动动画”改成“亲手完成游戏硬件适配并点火”，并根据 REDMAGIC 9 Pro+ 实机结果把肩键输入从标准 Android KeyEvent 扩展为证据驱动的 REDMAGIC SAR 只读链路。

## 首次启动流程

```text
纯黑 Starting Window
  ↓
横屏游戏手机硬件轮廓
  ↓
TAP L
  ↓
HOLD L（4 级震动 / 画面微共振）
  ↓
TAP R
  ↓
HOLD R（4 级震动 / 画面微共振）
  ↓
HOLD L + R
  ↓
整机点火：肩键视觉 + 主马达 + 屏幕共振 + 音效同步增强
  ↓
短暂收黑 / 静默
  ↓
GAME STAR BOX
  ↓
Runtime Gate 打开 → 主界面
```

首次完成后写入本地 `shoulder_calibrated_v1`。后续启动走缩短版自动点火，不再要求重复校准。

## 0.4.27 实机反馈与修正

首个测试 APK 在 REDMAGIC 9 Pro+ 上出现：**实体肩键灯效有响应，但竞界收不到按键输入。** 这说明肩键硬件已工作，但事件没有作为标准 Android `L1/R1` KeyEvent 进入 Activity。

公开工程 RedTrigger（MIT）提供了与该现象一致的平台证据：Nubia/REDMAGIC 肩键位于 SAR input device，左键对应 Linux `KEY_F7` / `0x41`，右键对应 `KEY_F8` / `0x42`；厂商游戏服务可能在 Android App 收到 KeyEvent 之前截获原始事件。

因此本分支增加两级修正：

1. 普通 `AndroidShoulderKeyAdapter` 继续支持 L1/L2/R1/R2，并增加证据明确的 Android `KEYCODE_F7/F8`；
2. 若 ROM 仍不向 Activity 派发事件，使用独立、只读的 Shizuku REDMAGIC SAR Reader，在首次校准前台生命周期内读取受信任 SAR 节点的 F7/F8。

## Core / Adapter 边界

### Core

`ShoulderBootStateMachine`：

- 不引用 Android、REDMAGIC、Shizuku、Settings、WebView 或 `/dev/input`；
- 只处理 `LEFT / RIGHT + DOWN / UP`；
- 强制顺序 `LEFT_TAP → LEFT_HOLD → RIGHT_TAP → RIGHT_HOLD → BOTH_HOLD → IGNITING → COMPLETE`；
- 单侧长按 1200 ms，联合点火 1450 ms；
- 输出 0~100 progress 和 0~4 haptic level。

新增 `ShoulderBootInputHub`，只作为进程内语义 rendezvous：平台 Adapter 发布 LEFT/RIGHT DOWN/UP，Core 状态机消费；不暴露设备路径、shell 或厂商细节。

### 普通 Android Adapter

`AndroidShoulderKeyAdapter`：

- `KEYCODE_BUTTON_L1/L2` → LEFT；
- `KEYCODE_BUTTON_R1/R2` → RIGHT；
- `KEYCODE_F7` → LEFT；
- `KEYCODE_F8` → RIGHT。

### REDMAGIC Privileged Adapter

新增：

- `IRedMagicShoulderReader.aidl`
- `IRedMagicShoulderCallback.aidl`
- `RedMagicShoulderReaderService`
- `RedMagicShoulderPrivilegedAdapter`
- `RedMagicShoulderBootstrapProvider`

权限链：

```text
REDMAGIC shoulder SAR
  ↓ Linux EV_KEY F7/F8
Shizuku UserService (read-only getevent)
  ↓ LEFT/RIGHT DOWN/UP only
ShoulderBootInputHub
  ↓
ShoulderBootStateMachine
```

Privileged Service 自行执行固定 `/system/bin/getevent -pl` 发现设备；调用方不能传路径。只有设备名包含 `nubia_tgk_aw_sar` 且节点格式为 `/dev/input/eventN` 的设备才能进入 Reader。Reader 只解析 F7/F8，其他原始输入不会跨 Binder。

## 特权工程宪法修订

原工程宪法规定 Shizuku 仅用于竞界自更新。本次新增能力前已建立强制补充条款：

`docs/ENGINEERING_CONSTITUTION_SHOULDER_INPUT_0.4.27.md`

新增白名单 capability 仅为：

`input.redmagic.shoulder.read`

它仅允许首次启动/显式重新校准期间只读 REDMAGIC SAR F7/F8；不得扩展成通用 shell、全局输入监控或输入注入器。

详细 Privileged Adapter 合同见：

`app/src/main/java/com/xbu/esportscenter/privileged/SHOULDER_READER.md`

## 视觉与音频

`shoulder-boot.html` 继续保持硬件优先设计：

- 横屏游戏手机轮廓；
- 左右肩键作为交互入口；
- 长按四级提升设备微振幅、屏幕回波频率、音效低频与整机 Vibrator 强度；
- L+R 点火阶段左右结构向中心收束，整机共振达到峰值后收黑；
- 最终显示 `GAME STAR BOX`，启动阶段不显示中文“竞界”。

当前音效使用 Web Audio 实时合成，用于先验证节奏与触感；正式 Sonic Logo 后续替换。

## 触觉策略

- TAP / 阶段确认：短 Click；
- HOLD level 1~4：重复波形逐级缩短间隔并提高振幅；
- IGNITING：一次性逐级增强的整机波形；
- 尊重 Android `HAPTIC_FEEDBACK_ENABLED`；
- 不宣称左右肩键内存在独立物理马达，方向感由整机马达 + 肩键局部画面反馈共同形成。

## 生命周期与 Runtime Gate

首次启动：

- 主 `index.html` WebView 后台加载但保持 `INVISIBLE`；
- 旧启动层立即 `done`，旧 `fairy_boot.ogg` 停止；
- `GSBRuntime.bootGateOpen()` 在点火完成前为 false；
- 游戏库、Session、Quick Menu、菜单音乐等后启动模块等 Gate 打开后才加载；
- REDMAGIC SAR Reader 只在 `BootMainActivity` 前台恢复状态绑定；pause/stop/destroy 立即停读；
- 校准完成检测到 `shoulder_calibrated_v1=true` 后立即停读并解绑 UserService；
- 覆盖安装上一版原型时，`shoulder_sar_migration_0427_v1` 仅执行一次：重置旧的肩键校准标记，强制真实 SAR 链重新校准，之后不再重复重置。

## 触摸恢复入口

启动页顶部 L/R 区域继续保留本地触摸入口，用于：

- Shizuku 不存在；
- 用户拒绝授权；
- 未识别到受信任 SAR；
- 非 REDMAGIC / 无肩键设备；
- 开发阶段单独验证震动和画面节奏。

触摸入口不会被标记成“实体肩键识别成功”。

## 安全边界

本次新增 Shizuku 能力，但权限面严格限定：

- 不新增 Android Manifest 权限；
- 不写 REDMAGIC / Android Settings；
- 不写 sysfs；
- 不使用 `sendevent`；
- 不使用 `input keyevent` / `input motionevent`；
- 不使用 uinput；
- 不生成虚拟手柄；
- 不把肩键映射成屏幕点击；
- 不接受 WebView/网络/用户输入提供的 shell 命令或 `/dev/input` 路径；
- 不转发 F7/F8 之外的原始输入；
- 不与 OTA Privileged Installer 合并 AIDL；
- Shizuku 失败不会阻止竞界普通功能。

## 红魔 9 Pro+ 实机测试矩阵

1. 冷启动不得出现旧圆环启动动画或旧启动音频。
2. 首次启动严格要求 TAP L → HOLD L → TAP R → HOLD R → L+R。
3. 实体左肩必须产生 LEFT DOWN/UP，实体右肩必须产生 RIGHT DOWN/UP。
4. 点按阶段长按超过 700 ms 不得误判为 Tap。
5. 单侧 Hold 未达到 100% 松手必须清零。
6. 四级 Hold 震动和画面共振应有清晰递进。
7. L+R 任一侧提前松开必须清零联合点火进度。
8. 标准游戏手柄 L1/L2/R1/R2 仍可驱动流程。
9. ROM 直接暴露 F7/F8 时无需 Shizuku Reader 即可驱动流程。
10. SAR Reader 只能发现受信任 Nubia SAR 节点并只输出 F7/F8。
11. 非 F7/F8 输入不得进入 Core。
12. Activity 切后台必须停止 reader 和持续振动。
13. Shizuku 被拒绝/未运行时不得崩溃，触摸恢复入口仍可完成首次启动。
14. 校准完成后不得残留 `getevent` reader。
15. 主界面 Runtime 只在 Gate 打开后加载，无旧启动闪回。
16. 第二次启动走 FAST 模式，不重复首次校准。
17. OTA 自更新 Shizuku 安全链无回归。
