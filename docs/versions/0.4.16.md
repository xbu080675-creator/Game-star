# Game Star Box 0.4.16 / versionCode 29

## Scope

Boot Runtime integration. This version connects the platform-neutral `BootOrchestrator` to the existing Game Star Box startup animation without changing the approved 0.4.14 visual design.

## Changes

- Added `BootMainActivity`, a thin launcher wrapper that exposes only semantic boot state through `GSBBoot`.
- Preserved historical component `com.xbu.esportscenter/.MainActivity` as an activity alias targeting `BootMainActivity`, so the fixed OTA restart command remains compatible.
- WebView reports `WEBVIEW_READY` through the narrow boot bridge.
- `native-update.js` reads real `BootSnapshot` progress and adjusts `fairy_boot.ogg` playback rate from 0.72x to 1.42x.
- The existing WebView boot animation remains audio-mastered, so visual motion, boot sound and haptic timing continue to share one clock while total real-world duration adapts to backend readiness.
- Slow startup stages reduce animation speed; `BOOT_COMPLETE` accelerates the remaining brand sequence instead of waiting for a fixed 4.02 seconds.
- Pure-visual fallback remains fixed-time if boot audio cannot start, prioritizing recoverability over a second independent animation clock.

## Security boundary

- `GSBBoot` exposes only `state()` and `webViewReady()`.
- It does not expose shell, Shizuku, Settings writes, Binder handles, arbitrary Intent forwarding, file access or vendor APIs.
- Core boot classes remain platform-neutral.
- No new Android permission is added.
- Existing self-update privileged whitelist is unchanged.

## Test matrix

1. Cold start: no white/default Android splash regression.
2. Normal REDMAGIC start: animation should finish faster than the former fixed 4.02 s when backend becomes ready quickly.
3. Slow/temporarily delayed REDMAGIC probe: boot animation should slow rather than jump directly to the UI.
4. Boot sound, logo motion and haptic cues must remain synchronized.
5. OTA install/restart must still work through the historical `.MainActivity` component alias.
6. Main UI, update panel, Shizuku self-update and REDMAGIC read-only monitoring must show no regression.
