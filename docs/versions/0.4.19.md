# Game Star Box 0.4.19 / versionCode 32

## 目标

把首页与游戏库从开发期默认示例游戏切换到本机真实游戏，并提供可控的“添加游戏”入口；同时保持 0.4.14 启动视觉、0.4.16 Boot Runtime、0.4.18 REDMAGIC 原生入口审计基线不回退。

## 本版完成

- 新增 `platform.android.InstalledGameCatalog`，只读查询带 `MAIN + LAUNCHER` 入口的本机应用。
- Android 26+ 优先使用 `ApplicationInfo.CATEGORY_GAME`，并兼容旧 `FLAG_IS_GAME`，自动识别系统已标记为游戏的应用。
- 真实游戏条目输出应用名称、包名与 128px 本地图标，不依赖网络封面或远端数据库。
- 首页原 5 个默认示例卡片不再显示 League of Legends / 无畏契约 / 王者荣耀 / 职业赛事 / 系统中心等开发期占位数据；运行时改写为真实已安装游戏。空位显示“添加游戏”，不是伪造游戏。
- “继续游玩”区域移除开发期虚构战绩、时长、训练模式等游戏数据，改为真实已添加游戏的快捷启动项。
- 游戏库移除 Demo/Cloud/Steam/Apex/Minecraft 等默认示例条目，动态渲染真实游戏，并显示实际游戏数量。
- 游戏库新增“添加游戏”入口。对于没有被 Android 标记为 `CATEGORY_GAME` 的游戏，可从本机可启动应用列表手动加入；选择保存在本机 `localStorage`，可再次点击移除。
- 新增窄 `GSBGames` WebView bridge：
  - `catalog()`：只读获取自动识别游戏与可启动应用列表；
  - `launch(packageName)`：只接受当前 `MAIN/LAUNCHER` 枚举 allow-list 中的包名，再获取系统 launch intent。
- Android 11+ `<queries>` 增加 `MAIN + LAUNCHER` intent visibility，但明确不申请 `QUERY_ALL_PACKAGES`。
- `native-update.js` 负责加载独立 `game-library.js`，避免继续把首页、OTA、菜单音乐与游戏库逻辑揉在同一个文件。
- CI 新增 Installed Game Catalog Guard，防止后续为图省事加入 `QUERY_ALL_PACKAGES`、shell、Shizuku 或 Settings 写入。

## 安全边界

- 不提供任意包名启动器：JS 传入的包名必须重新通过本机 launcher allow-list 验证。
- 不扫描无启动入口的后台/系统包，不申请 `QUERY_ALL_PACKAGES`。
- 不调用 Shizuku、不执行 shell、不写 Settings、不写 sysfs。
- WebView 只能请求“列出可启动应用 / 启动已验证应用”，不能构造 Intent、Component、URI、flags 或 vendor 参数。
- 手动添加只改变竞界本地游戏库选择，不修改系统应用状态、不向红魔游戏空间写入任何配置。

## 架构职责

```text
Android PackageManager
        ↓
InstalledGameCatalog (Platform Adapter)
        ↓
GSBGames typed bridge
        ↓
game-library.js
        ↓
首页 / 游戏库 / 添加游戏
```

Core 不依赖 PackageManager，Android 游戏枚举逻辑全部留在 Platform Adapter。

## 实机测试重点

1. 冷启动后首页不应再出现任何默认示例游戏名称。
2. Android 已标记为游戏的本机应用应自动出现在首页/游戏库。
3. 游戏图标、名称、包名应与系统真实应用一致。
4. 点击“启动”应进入对应真实游戏。
5. 未被系统标记为游戏但具有 Launcher 入口的应用，应能通过“添加游戏”加入并启动。
6. 再次在添加列表点击手动项目，应能从竞界游戏库移除，不卸载应用。
7. 竞界自身不应出现在候选列表。
8. 0.4.14 启动动画、0.4.16 动态 Boot、OTA 与 REDMAGIC 审计不应出现回归。

## 已知边界 / 下一阶段

- 本版的“真实游戏”来源首先是 Android 系统游戏分类 + 用户手动添加，尚未读取红魔 Game Space 自己的游戏白名单数据库。
- 部分厂商/侧载游戏可能没有正确设置 Android game category，因此需要手动添加；下一阶段可在确认稳定、只读的 REDMAGIC 游戏列表入口后，将其作为额外 discovery source。
- 游戏启动已是真实动作，但 `GameSession` 还没有完整绑定到目标进程前后台生命周期；后续会把 `PREPARING → LAUNCHING → RUNNING/SUSPENDED` 与真实游戏启动/切换事件对齐。
- Quick Menu 后续按当前游戏 packageName 绑定每游戏 Profile、REDMAGIC 性能策略和插件能力。
