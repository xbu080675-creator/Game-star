# Game Star Box 0.4.25 / versionCode 38

## 目标

修复触屏手势导航完全失效的问题，恢复主界面上下切换菜单与首页左右切换游戏卡片的触控操作，同时不破坏已通过的点击、键盘/手柄语义和启动动画性能隔离。

## 根因

现有前端只实现了：

- 顶部 Tab 点击切换场景；
- 首页卡片点击选择；
- 键盘 / 手柄方向键通过 `keydown` 切换场景或卡片。

但没有任何 `touchstart/touchmove/touchend` 或 Pointer Gesture 导航实现。因此在 Android WebView 上用手指向上/向下滑动时，页面没有对应导航动作；由于整体页面本身又使用固定主机式布局、`overflow:hidden`，手势看起来就是完全失效。

## 本版完成

- 新增 `app/src/main/assets/gesture-runtime.js`。
- 启动动画结束后由 `native-update.js` 延迟加载，避免重新影响启动动画帧预算。
- 竖向滑动：在首页 / 游戏库 / 电竞 / 系统四个主场景之间切换。
- 首页横向滑动：在游戏卡片之间切换。
- 使用 Pointer Events，兼容 Android WebView 触屏输入。
- 增加 42px 位移阈值、900ms 时间阈值和主轴 1.15 倍判定，降低误触。
- 按钮、Tab、输入框、开关等交互控件默认不触发全局滑动导航。
- Quick Menu 打开时不抢占主场景手势。
- 启动动画未结束时禁用手势，避免首屏误操作。

## 安全与架构边界

- 纯前端输入层修复，不新增 Android 权限。
- 不接入 Shizuku、shell、Settings 写入或厂商控制接口。
- 不修改 Core / Adapter 边界。
- 通过点击现有 Tab / Card 复用已有 UI 状态机，不建立第二套场景状态源。

## 实机测试重点

1. 启动动画结束后，在页面空白区域上滑/下滑，四个主菜单应逐项切换。
2. 首页游戏卡片区域左右滑动，焦点游戏应随手势切换。
3. 点击顶部 Tab 仍正常。
4. 点击按钮和开关时不能被误识别成滑动。
5. Quick Menu 打开后，主页面滑动不得穿透。
6. 0.4.24 启动动画流畅度不得回归。
7. 0.4.22 游戏库性能优化和 0.4.20 Game Session 不得回归。
