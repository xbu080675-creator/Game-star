# Game Star Box 0.4.18 / versionCode 31

## 目标

把 0.4.17 的“REDMAGIC 能力存在性普查”推进到“原生入口审计”，但仍然只做只读证据采集，不提前接管任何厂商控制接口。

## 本版完成

- 新增 `RedMagicNativeEntryAudit`：只读取 `cn.nubia.gamelauncher` 与 `cn.nubia.gameassist` 的包元数据，枚举 exported Activity / Receiver / Service / Provider。
- 新增 `RedMagicNativeEntryAuditSnapshot`：记录包可见性、exported 组件总数、与游戏/性能/通知/内存/网络/Game Tools 关键词相关的候选入口。
- Android 11+ Manifest 增加精确 `<queries>`，只允许竞界看见 `cn.nubia.gamelauncher` 与 `cn.nubia.gameassist`，修复包可见性导致的“系统里明明有但 probe 误判不存在”。该声明不新增权限。
- `GameStarBoxApplication` 将审计结果发布为 `platform.redmagic.exported_entry.evidence`，并用稳定 `detailCode` 区分 performance / interruption / memory / network 候选证据。
- 语义 capability 仍保持 `UNKNOWN`；发现 exported component 只代表“存在可继续审计的入口”，不代表可安全调用。
- `[GSB-RM]` 日志新增 exported 数量、候选数量、四大 P0 分类数量和最多 12 个候选组件名称/声明权限，方便红魔 9 Pro+ 实机收集。

## 外部证据与结论

### RedTrigger

公开源码确认红魔侧确实存在 `nubia_game_scene`、`nubia_game_mode`、`cc_game_mis_operate` 等 Global Settings；该项目通过 Shizuku / secure-settings 能力写入这些值。我们当前只把这些信息视作“游戏模式/肩键链存在”的证据，不把它直接等同于完整性能增强能力。

### NubiaToolkit

公开源码显示 `cn.nubia.gameassist` 内部存在：

- `CleanAnimationController.startClean()`；
- `com.zte.performance.mindsync.MindSyncManager.startBgAppCleanupFromGameMode(...)`；
- `OneMoreThingManager.linkOMTProvider("kill", Bundle)`；
- `com.zte.gameassist.common.GameCheck.isGameSpaceListApp(...)`。

这些证据说明红魔 Game Assist 内部确实包含后台清理与游戏识别链，但该项目依赖 Xposed/LSPosed Hook；因此这些内部方法不能被竞界当成稳定公开 API 直接反射/注入调用。

## 安全边界

`RedMagicNativeEntryAudit` 明确禁止：

- `startActivity` / `startService` / `bindService`；
- `sendBroadcast`；
- `ContentResolver.call()` 或 Provider 主动调用；
- 任意 Settings 写入；
- Shizuku / shell / root；
- sysfs 写入；
- 反射进入 `cn.nubia.gameassist` 私有类。

本版只读 PackageManager 元数据。

## 实机重点

升级后重点记录：

```text
[GSB-RM] native-entry exported=...
[GSB-RM] native-entry candidates=...
[GSB-RM] native-entry candidate kind=... class=... permission=...
```

优先关注候选中是否出现明确的 performance / game mode / notification / disturb / clean / network / qos / fan 等服务或 Provider。

## 下一阶段

如果实机发现明确 exported 且权限可满足的厂商组件，则逐个做静态契约审计：Intent action / Provider authority / Binder permission / 参数范围 / 回滚路径。只有完成这些审计并能 Fail Closed 后，对应 capability 才能从 `UNKNOWN` 升级为 `AVAILABLE`。
