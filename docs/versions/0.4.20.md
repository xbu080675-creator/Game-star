# Game Star Box 0.4.20 / versionCode 33

## 目标

把 0.4.19 已经完成的“真实游戏枚举 + 真实启动”正式接入 Game Session 生命周期，让“添加游戏 → 启动 → 离开竞界进入游戏 → 返回竞界”不再只是一次 Android launch intent，而是进入统一的 session runtime。

同时继续保持以下已验收基线不回退：

- 0.4.14 启动视觉；
- 0.4.16 Boot Runtime；
- 0.4.18 REDMAGIC 原生入口只读审计；
- 0.4.19 真实游戏库与受限 launcher allow-list。

## 本版完成

- 新增 `platform.android.AndroidGameSessionLauncher`，作为 Android 游戏启动 Adapter。
- 真实游戏首次启动时建立语义链：
  - `IDLE → PREPARING → LAUNCHING`
  - 竞界因目标游戏启动离开前台时：`LAUNCHING → RUNNING`
  - 从游戏返回竞界时：`RUNNING → SUSPENDED`
- 对同一已挂起游戏再次点击“返回游戏”时，使用已有 session 恢复为 `RUNNING`，不伪造新 session。
- 切换到另一个游戏时，旧 session 先安全 `ENDED → IDLE`，再为新 package 建立 `PREPARING → LAUNCHING`。
- Android `startActivity` 失败时，新增回滚路径，避免 session 永久卡在 `PREPARING/LAUNCHING`。
- 稳定日志新增 `[GSB-GAME]`：记录 launch accepted、RUNNING、SUSPENDED 和 `GSB-GAME-LAUNCH-FAILED`。
- `BootMainActivity` 新增只读 `GSBSession` bridge：
  - `state()` 只返回 `{ state, gameId }`；
  - 不暴露任意状态写入方法。
- 新增 `session-runtime.js`，把 native GameSession 状态反馈到首页真实游戏卡：
  - PREPARING / STARTING；
  - CURRENT SESSION // RUNNING；
  - CURRENT SESSION // SUSPENDED；
  - “返回游戏”按钮。
- `native-update.js` 独立加载 `session-runtime.js`，保持 OTA、游戏库、Session、菜单音乐继续模块化。

## 状态语义

```text
首次启动真实游戏
IDLE
  ↓
PREPARING
  ↓
LAUNCHING
  ↓ 竞界 onStop
RUNNING
  ↓ 返回竞界 onResume
SUSPENDED

再次返回同一游戏
SUSPENDED
  ↓ Android 接受 launch intent
RUNNING

切换游戏
SUSPENDED / RUNNING
  ↓
ENDED
  ↓
IDLE
  ↓
PREPARING(new package)
  ↓
LAUNCHING
```

## 重要边界

本版的 `RUNNING/SUSPENDED` 判断来自竞界自身 Activity 前后台生命周期与“由竞界发起的已验证游戏启动”，不是全局进程窥探。

因此：

- 不申请 Usage Access；
- 不使用 Accessibility；
- 不轮询系统前台进程；
- 不调用 shell / Shizuku / root；
- 不声称能够判断用户离开竞界后是否又手动切去了第三个应用。

这是当前无额外权限条件下可恢复、低侵入的第一阶段 Session Runtime。后续如果 REDMAGIC 原生 Game Space 提供稳定的游戏前台状态入口，可把它作为平台证据源补强，而不是把 vendor 逻辑写进 Core。

## 安全边界

- packageName 仍必须先通过 `InstalledGameCatalog` 当前 `MAIN + LAUNCHER` allow-list。
- WebView 仍不能提供 Intent action、component、URI、flags 或任意 Android 参数。
- Session bridge 只读，UI 不能直接改 Core 状态。
- 不新增系统权限。
- 不扩大 Shizuku Privileged Adapter；OTA 特权白名单仍只服务竞界自身更新。
- 不写 REDMAGIC Settings、不调用厂商 Binder/Provider/Service、不写 sysfs。

## 架构职责

```text
WebView 游戏按钮
      ↓ packageName
GSBGames typed bridge
      ↓
InstalledGameCatalog allow-list validation
      ↓
AndroidGameSessionLauncher
      ├─ Android startActivity
      └─ GameSessionManager semantic transitions
               ↓
         GSBSession read-only bridge
               ↓
         session-runtime.js
```

Core 仍然完全不知道 Android Activity、Intent、PackageManager 或 REDMAGIC。

## 实机测试重点

1. 首页/游戏库中的真实游戏点击后能正常进入游戏。
2. 点击后日志应先出现 `PREPARING → LAUNCHING`。
3. 游戏真正接管屏幕后应出现 `LAUNCHING → RUNNING`。
4. 返回竞界后应出现 `RUNNING → SUSPENDED`。
5. 当前游戏卡应显示 `CURRENT SESSION // SUSPENDED`，按钮显示“返回游戏”。
6. 再点同一游戏，应恢复 `RUNNING`，不能创建重复 session。
7. 从挂起游戏切换到另一游戏，应先结束旧 session，再建立新 session。
8. 无效/消失的 launcher intent 不应让 session 卡死。
9. OTA、启动动画、真实游戏库、REDMAGIC 只读审计不得回归。

## 下一阶段

- 将 REDMAGIC 只读审计结果与当前 `gameId/packageName` 关联，为“当前游戏 Profile”准备证据层。
- 继续审计性能增强、通知屏蔽、内存清理、网络加速的稳定原生入口。
- Quick Menu 开始读取 `GSBSession + GSBCapabilities`，做到“当前是哪个游戏、哪些能力可用”真实联动。
- 若能找到 REDMAGIC 稳定游戏前台/游戏白名单入口，再补强 Session 的 RUNNING/SUSPENDED 判定。
