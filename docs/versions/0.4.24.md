# Game Star Box 0.4.24 / versionCode 37

## 目标

修复启动动画本体在后端加载期间出现明显掉帧、顿挫的问题。该问题不是动画时间轴速度不合适，而是启动动画渲染期间仍有 REDMAGIC 探测、CapabilityRegistry 推送和 JS/Native bridge 轮询占用主线程，导致 WebView 无法稳定提交帧。

## 根因

1. `RedMagicEntryMonitor` 的 `ContentObserver` 绑定 Android Main Looper，首次启动时 `emitSnapshot()` 以及后续 `onRedMagicSnapshot()` 链路会在 UI 线程执行。
2. `onRedMagicSnapshot()` 会继续执行 REDMAGIC capability probe、PackageManager exported component audit、能力状态发布与日志，启动阶段可能形成连续主线程工作。
3. `CapabilityRegistry.publish()` 每次状态变化都会触发 `BootMainActivity` listener，随后 `evaluateJavascript()` 回推整个 capability snapshot；REDMAGIC 首次探测会连续发布多项 capability，因此动画期间会产生多次 WebView 主线程回调。
4. `native-update.js` 原先还周期性调用 `GSBBoot.state()`，虽然单次开销不大，但属于启动动画期间不必要的 JS/Native bridge 轮询。

## 本版修复

- `RedMagicEntryMonitor` 新增专用 `HandlerThread("GSB-RedMagicProbe")`。
- Settings 读取、首次 snapshot、ContentObserver 回调以及后续 REDMAGIC probe/audit 全部从 Main Looper 移出。
- `BootMainActivity` 新增窄桥 `GSBRuntime.ready()`。
- Capability 和 GameSession listeners 不再在 Activity 创建时立即挂载；只有启动动画结束、Post-Boot Runtime 开始时才启用。
- 启动动画期间不再向 WebView 连续推送 capability/session snapshot。
- `native-update.js` 删除 320ms 周期性 `GSBBoot.state()` 轮询，改为初始读取 + Native 事件推送。
- 0.4.23 已完成的固定 1.0x 动画时钟和 Post-Boot 脚本延迟加载继续保留。

## 性能边界

启动阶段主线程只保留：

- Activity / WebView 必需生命周期；
- 启动动画本身；
- 极少量 Boot semantic state 推送；
- 必要的触觉与音频控制。

以下工作不得重新进入启动动画主线程路径：

- REDMAGIC Settings / PackageManager 探测；
- exported component audit；
- 全量 capability 状态推送；
- 游戏库扫描与图标处理；
- Quick Menu / Session Runtime 初始化；
- 周期性 JS/Native bridge polling。

## 安全边界

- 不新增权限。
- 不新增 Shizuku、root、shell 能力。
- REDMAGIC adapter 仍然只读。
- `GSBRuntime.ready()` 只允许启用本地状态 listener，不接受参数，不执行系统动作。
- Core / Adapter 分层不变。

## 实机验收

1. 冷启动进入 GAME STAR BOX 动画后，动画运动应连续，不再出现加载过程中一顿一顿的感觉。
2. 音频和画面继续保持 1.0x 原时间轴同步。
3. 动画结束后才开始加载真实游戏库、GameSession Runtime、Quick Menu 与菜单音乐。
4. Quick Menu 仍能收到 capability/session 实时更新。
5. REDMAGIC 竞技键/Settings 变化仍能被监控。
6. 0.4.22 游戏库性能修复不得回归。
7. OTA、签名、启动黑场基线不得回归。

## 结论

启动动画属于首屏实时渲染路径，必须按高优先级渲染任务处理。后端加载可以慢，但不能抢动画帧预算。后续任何新增启动任务默认异步，并且不得在动画阶段向 WebView 高频推送非必要状态。
